文档来源与依据

本文档是对《产品设计文档 v1.0》的工程化落地，承接已交付的可交互原型与技术路线图（Dart+Flutter 版）。三者关系：产品设计文档（做什么）→ 技术路线图（用什么做、何时做）→ 本开发设计文档（怎么做、模块怎么拆、接口怎么定）。所有内容均为原创设计，不复刻任何第三方美术、数据与文案。

01概述与范围

1.1产品定位

一款统一兵棋引擎驱动的硬核策略手游，以「职业模式」承载拟真玩法，以多时期地图副本做长线内容。仅移动端（iOS / Android），免费下载 + 内购（仅副本与外观，禁 pay-to-win）。

1.2设计目标

一套内核

职业/专业/娱乐三模式共用仿真内核，由四杠杆差异化。

确定性可回放

固定步长 + 种子随机，战报可回放、异步回合可对拍。

移动优先

中低端机性能基线；2.5D 轻 3D；情境操作条。

1.3范围与边界

范围项本期（MVP / P0–P2）边界外（P3+）
模式职业模式完整专业模式、娱乐模式
副本二战东线（首发）其他时期、UGC 剧本
平台iOS / AndroidWeb / PC 客户端
商业化副本解锁、外观涂装内购订阅、Battle Pass
社交公会、排行榜基础实时协作推演

02总体架构

延续技术路线图的四大支柱，落地为四层技术架构；仿真内核（①）与表现层（③）严格解耦，Dart 内核两端可运行（客户端预览/UGC 沙盒 + 服务端权威结算）。

① 统一引擎层（client-agnostic core · Dart 纯逻辑）
六边形网格引擎单位 / 状态机作战解析器 后勤 · 补给线解算指挥官 / 士气 / 疲劳回合调度器 规则开关层（Mode Layer）AI 决策（效用 / 行为树 / 搜索）
② 内容副本层（data pipeline）
副本 DAG 剧本格式地图 / 单位 / 涂装资产配置数值平衡表（CF 系数外置） 合规敏感度分级服务内容版本与灰度下发
③ 移动平台层（iOS / Android · Flutter）
Flutter 客户端六边形渲染 / 2.5D（CustomPainter · three_dart）情境操作条 UI 云存档（OSS）推送（APNs / FCM）异步回合客户端
④ 商业 · 社交层（services）
账号 / 统一登录支付 / 内购（副本·外观，禁 pay-to-win）公会 / 排行榜服务 UGC 剧本编辑器 + 审核管线运营后台 / 数据埋点防沉迷合规

部署拓扑

Flutter 客户端⇄ gRPC/WS API 网关→ 对局/异步回合服务→ Dart 权威内核（无状态重算）↔ PostgreSQL + Redis
云存档 / 资源→ OSS 支付 / 推送→ 渠道 SDK 运营后台 + 埋点→ 数仓

客户端内核与内核服务均消费同一份 core 包；UGC 编辑器在客户端本地用同一内核做沙盒推演校验，避免非法副本上传。

03仿真内核详细设计

内核是全部模式与副本的复用底座，须最先稳定。用 Dart 编写为纯逻辑 core 包，不依赖 Flutter / 任何渲染 API。对外暴露「指令 → 状态快照」的纯函数式接口。

3.1六边形网格引擎

坐标系统：采用 轴向坐标（Axial, q/r） 为主键，内部统一转换为立方坐标（Cube, x+y+z=0）做距离与邻接运算，避免浮点误差。

能力算法 / 公式说明
邻接6 个方向偏移常量立方坐标加方向向量
距离dist = (|dx|+|dy|+|dz|)/2立方曼哈顿距离
视线（LOS）超覆盖线（Supercover） + 高度遮挡判定地形高度差阻断视线
寻路A*（启发式为六边形距离）代价含地形机动惩罚
范围环 / 螺旋 / 视野扇形基于距离上限枚举
确定性要求：邻接与距离运算全部为整数/定点运算，禁用浮点距离比较；枚举类遍历使用 List 等有序容器。

3.2单位模型

单位为核心实体，采用组件化数据类（非继承），便于模式开关裁剪字段。

class Unit {
  UnitId id;
  Faction faction;            // 阵营
  UnitType type;              // 装甲/步兵/炮兵/空军...
  AxialCoord pos;             // 当前格
  int strength;               // 建制完整度（0–100）
  int morale;                 // 士气（0–100）
  int fatigue;                // 疲劳（0–100）
  double supply;              // 补给率（0–1，见 3.4）
  Equip equip;                // 装备/涂装（外观不影响数值）
  // 七维属性（用于 CF 计算，见 3.3）
  Stats stats;                // 机动/火力/防护/侦察/补给/指挥/协同
}

状态机：待命 → 机动 → 交战 → 溃散/伤亡 → 重组，状态切换由事件驱动，可回放。

3.3作战解析器与 CF 公式

战斗力指数 CF（Combat Factor） 采用系数乘积模型，由基础战力与若干情景系数相乘得出，便于数值表外置与热更：

CF = BasePower(type)
   × K_terrain(地形修正)
   × K_strength(建制完整度)
   × K_supply(补给率, 见 3.4)
   × K_morale(士气)
   × K_commander(指挥官加成, 见 3.6)
   × K_counter(兵种克制)

交战结算（单次对射 / 突击）：
  ratio   = CF_attacker / CF_defender
  lossDef = AttBase × f(ratio, distance, cover)
  lossAtk = DefBase × g(ratio, distance, cover)
  其中 f,g 为损耗模型，cover 取守方地形掩体系数

设计说明

CF 系数（K_*）与损耗模型的曲线参数均落在数值平衡表（CSV/JSON），由运营与平衡团队外置调参，无需发版。地形掩体、兵种克制矩阵同样外置，保证数据驱动平衡原则。

3.4后勤与补给线（护城河）

后勤是产品的核心差异化（护城河）。单位补给率随距补给源跳数呈指数衰减：

R(d) = R₀ · e^(−k · d)

  R₀   : 源点满补给率（=1）
  d    : 沿补给线的跳数（hex 距离）
  k    : 衰减系数（数值表外置，如 k=0.18）
  • 补给线由最短路径（Dijkstra） 从各补给源（ depot ）计算到每个单位格的 d。
  • 补给率影响 CF 的 K_supply 项：R < 0.4 时单位进入「补给不足」，火力与机动显著下降；R≈0 时快速掉士气、掉建制。
  • 被切断的补给线（路径被敌方单位/控制格阻断）立即重算，体现「护城河」的战术价值。
性能：补给图解算在回合推进时增量更新（受影响区域重算），非全图暴力重算；P4+ 热点可下沉 Rust。

3.5状态系统（士气 / 疲劳 / 补给）

三类状态互相耦合，构成「拟真」手感：

状态变化驱动影响
士气 morale胜负、补给、指挥官、友邻溃散CF 的 K_morale；低于阈值触发溃散
疲劳 fatigue每机动/交战累积，补给充足时回落机动范围与 CF 下降
补给 supply由 3.4 解算联动士气/建制

3.6指挥官系统

  • 指挥半径：半径内单位获得 K_commander 加成（基于指挥官等级与特性）。
  • 技能：主动技能（如「集中突击」「坚守」）触发短暂修正；被动特性（如「机动专家」）常驻加成。
  • 指挥官作为独立实体参与回合调度，技能消耗「指挥点」，由回合推进恢复。

3.7回合调度器

确定性推进核心。每个回合 = 若干「阶段（Phase）」的有序序列：

补给结算→ 状态更新→ 指令受理（机动/交战/技能）→ 交战结算→ 损耗/重组→ 回合终（产出快照+事件流）

调度器产出 状态快照（供客户端渲染）与 事件流（供服务端 Event Sourcing 持久化与异步回放）。

3.8确定性约束（落地清单）

维度约束实现手段
时间固定步长 / 定长回合回合内指令按统一顺序确定性受理
随机种子 RNG自实现 SeededRNG（mulberry32 等），禁用 Random()
顺序无遍历顺序依赖用 List/排序后的有序结构，避免 Map 无序迭代参与结算
浮点规避跨平台差异定点数或显式阈值比较；损耗取整
对拍自动回归CI 内同一种子双端重算，校验快照一致

04模式与四杠杆

三模式共用内核，由四杠杆差异化，实现于「规则开关层（Mode Layer）」：

杠杆职业模式（MVP）专业模式（P3）娱乐模式（P4）
规则开关全规则（补给/士气/损耗完整）更细粒度可选规则简化规则
信息密度全信息（迷雾/补给率可见）拟真迷雾 + LOS信息降噪（自动提示）
AI 强度效用 AI + 中搜索深度深搜索 / ML轻量 AI
单局时长中等（异步回合）长线短平快
原则：新增模式只改 Mode Layer 配置，不动内核逻辑，避免多套代码。

05客户端架构（Flutter）

客户端负责呈现 + 输入，不承载任何规则。战斗渲染采用 2.5D 轻 3D（轴测投影 / three_dart），其余界面以 Widget 实现。

分层

  • 表现层：页面/组件（首页、副本、战斗、商店、军团、战报、编辑器、设置）
  • 状态层：Riverpod / Bloc，绑定内核快照
  • 内核桥接：本地 core 包（离线预览 + UGC 校验）
  • 网络层：gRPC/WS 客户端、云存档、推送

渲染策略

  • 六边形战场：CustomPainter 轴测投影，高度层用 y 偏移 + 侧面
  • 单位：低面数立牌 / 图标，立于格上带投影
  • 相机：斜 45° 俯视，双指缩放；LOD 随缩放切换
  • 特效：攻击/合围/补给线用轻量光效，不喧宾夺主
渲染层只消费内核状态快照，不参与确定性计算；换美术风格/引擎对战斗逻辑无感。UGC 编辑器在客户端用同一内核做推演校验，非法副本不上传。

11合规设计

题材敏感度分级（by Design）

内容分级服务对副本/剧本打敏感度标签。高敏感题材（抗战 / 解放战争 / 抗美援朝等）隔离评估，未通过评估前不公开、不进入 UGC 发布。合规前置，而非事后补丁。

  • 内购公平底线：仅副本与外观涂装，禁 pay-to-win，常驻声明于商店页。
  • 防沉迷：实名接入、时长限制、健康提示，置于设置页合规区。
  • UGC 审核管线：自动初筛（敏感词/题材标签）+ 人工复核，发布前卡口。
