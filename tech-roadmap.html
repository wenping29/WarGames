铁幕兵棋 HEXFRONT

PRODUCT TECHNICAL ROADMAP · v0.1 · 对齐《产品设计文档 v1.0》

本路线图以设计文档的「统一兵棋引擎」为核心，沿四大支柱（引擎层 / 内容副本层 / 移动平台层 / 商业·社交层）展开技术架构，并以MVP → 职业完整化 → 商业发布 → 专业模式 → UGC/娱乐 → 智能化运营的分阶段节奏落地。所有技术选型均为建议，落地时以团队现状与成本为准。

一 · 技术愿景与设计原则

一套内核，多模式分层

仿真内核与表现层解耦；职业/专业/娱乐三模式共用内核，仅由「规则开关 · 信息密度 · AI 强度 · 单局时长」四杠杆差异化，避免维护多套代码。内核以 Dart 实现，两端可运行：客户端内即时预览与 UGC 沙盒就地校验，服务端跑权威异步结算；UGC 编辑器天然内建推演校验。

确定性 & 可回放

战斗采用确定性仿真（固定步长 + 种子），保证多端一致、战报可回放、对拍可自动化，是公平性与异步回合的底座。

合规内建（by Design）

题材敏感度分级、内容审核、防沉迷在架构与流程中前置，而非事后补丁；高敏感题材（抗战/解放/援朝等）隔离评估。

移动优先 · 性能优先

以中低端机为性能基线：LOD 聚合、情境操作条、信息降噪；启动时间、帧率、崩溃率纳入发布门禁。

数据驱动平衡

CF 系数、损耗模型、AI 权重外置为数值表，支持热更与 A/B；运营与平衡团队可直接调参，无需发版。

异步即服务

回合推进与结算上云，客户端只负责呈现与输入；天然支撑碎片时间推演与推送通知。

五 · 关键技术挑战与对策

确定性仿真内核

浮点/随机/顺序差异会破坏一致性与回放。对策：固定步长 + 种子 RNG + 无平台依赖的纯逻辑层，配自动对拍测试门禁。

后勤指数衰减解算

补给线随距离 R(t)=R₀·e^(−kt) 衰减，需图遍历 + 缓存。对策：增量解算 + 脏标记，避免每帧全量重算，保移动端帧率。

多模式规则开关架构

单代码基出三模式易腐化。对策：模式 = 四杠杆参数集（特性开关 + 数据配置），模式逻辑全部数据驱动，禁止散落 if 分支。

移动端性能 / LOD

大地图 + 大量六边形单位压垮中低端机。对策：低缩放合并单位/简化地形，高缩放展开细节；对象池 + 批渲染。

异步回合一致性

离线推进与冲突解决。对策：Event Sourcing 指令流 + 云端确定性重算，客户端仅提交指令，天然支持断线续玩。

合规内建

题材敏感与未成年人保护是红线。对策：分级标签库 + 自动化初筛 + 人工复核双轨；防沉迷接入实名/时长，高敏感题材默认隔离。

六 · 工程组织与发布门禁

团队构成（建议）

  • 引擎组：仿真内核 / 六边形 / 后勤 / 渲染
  • 客户端组：Flutter / UI / 移动适配
  • 服务端组：对局 / 异步回合 / 社交 / 支付
  • AI 组：效用 AI / 搜索 / 平衡
  • 工具链组：DAG 编辑器 / 数值 / UGC / 合规
  • QA：内核对拍 / 性能 / 合规测试

研发节奏

  • 双周迭代 + 垂直切片（每阶段先出可玩切片）
  • 内核单测覆盖率门禁；回放对拍纳入 CI
  • 灰度发布 + AB；监控崩溃/帧率/埋点

发布门禁 KPI

启动≤4s战斗≥45fps崩溃＜0.5%包体≤300MB异步延迟＜3s合规 100% 过审

七 · 主要风险与依赖

高
仿真内核延期 → 阻塞所有模式与副本；对策：P0 集中资源，内核先于一切，设确定性对拍门禁。
高
合规不确定性 → 影响高敏感题材与 UGC 发布节奏；对策：合规前置设计，分级隔离，预留评估周期。
中
移动端性能 → 影响硬核信息密度下的留存；对策：LOD + 信息降噪 + 性能基线机型纳入门禁。
中
AI 难度失衡 → 三模式体验落差；对策：规则开关 + 搜索深度分层，数据驱动调参。
低
多模式代码腐化 → 维护成本上升；对策：模式参数化，禁止散落分支，架构评审。
